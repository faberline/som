## Runtime evidence and its limits

The checks create an isolated real PostgreSQL database or MongoDB replica-set
namespace. They install dependencies, migrate, start Uvicorn and send HTTP
requests. The service code has no test route or authentication bypass.

The tester pauses an actual database write or checkpoint.
It observes committed rows from a separate database connection.
It then injects a failure in the test database.
It checks the journal and physical rows after compensation.

The saved PostgreSQL and MongoDB diagnostics prove:

- Default CRUD, filters, page bounds, restart and migrations.
- Idempotent flow results and changed-content conflicts.
- Flow route authentication and run-owner isolation.
- Compensation after parent and child writes have committed.
- Preservation of rows changed by an independent request.
- Heartbeat renewal during a held business transaction.
- Rejection of an old executor after recovery advances the epoch.
- Single recovery ownership when two requests race.
- Heartbeat failure stops forward writes and rolls back uncommitted rows.
- Committed rows and journal records survive a forced process kill.
- Restart and repeated requests do not replay forward work.
- Recovery after restart only reverses committed effects.
