## 目的

驗證 CNL／JSON 語意等價、完整診斷及下游相容。
比較輸入成本時，先固定相同的產物交付方式。

## 完成條件

- [ ] 使用既有服務及流程案例覆蓋全部現有語意。
- [ ] 欄位、順序、引用、分支、權限、交易及補償全部一致。
- [ ] Python／Rust 的有效結果及拒絕類別一致。
- [ ] 缺漏、矛盾、錯誤引用及作用範圍錯誤確實失敗。
- [ ] 固定模型與 decoder 後，模型輸入及下游相容。
- [ ] 舊格式、回歸、嚴格 Python 品質及獨立行為檢查全部通過。
- [ ] 封存原始 CNL、解析摘要、prompt、模型輸入及產物。
- [ ] 每項結果綁定同一來源、grammar、契約、工具及模型雜湊。
- [ ] 輸入成本包含 grammar 文件、讀取、診斷及重試。
- [ ] 缺少用量保持空白。近似 token 數與代理實際用量分開報告。
- [ ] 按需讀取的節省不混入 CNL／JSON 比較。
- [ ] 不宣稱較短 prompt、語法接受或型別正確已證明需求正確。

## 執行順序

先做本機等價及解析測試，再評估付費代理對照或完整新訓練。
第一階段不因更換需求入口增加 App。
直接寫碼數據永久保留。
同一 App 的需求及驗收不變時，重用原 direct 基線。
只有新增 App 才收集新基線。

## 邊界

M2 持續執行，不能用 M7 證據代替 M2 關卡。
M6、64 KiB 上限及按需讀取的規則仍未另行批准。
不切換 current，不回填舊結果，也不混用歷史最好結果。
